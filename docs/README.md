### Что означает решение по Р3

Пользователь выбрал показывать оба протокола раздельно. Основной — блоки 6+2+2 с
гейтами; дополнительно, отдельным экраном, — буквальный walk-forward из п. 1.3 без
гейтов, чтобы видеть расхождение двух оценок. Расхождение между ними само по себе
диагностично: если буквальный walk-forward показывает заметно лучший результат, чем
блочный протокол, это мера того, сколько даёт подглядывание в закрытые сезоны.
Требует дополнительной работы на этапе 6 — учтено в плане.

Также сработали два триггера из п. 13:

- **«спецификация противоречит сама себе»** — п. 1.3 (walk-forward) и п. 8
  («результат по каждому OOS-окну» для зафиксированной стратегии) описывают
  два разных протокола. Разбор: [07-spec-review.md](07-spec-review.md), С3.
- **«спецификация не покрывает возникший случай»** — п. 1.2 определяет всё
  через `p̂`, но п. 5 требует азиатские четвертные форы, у которых исход не
  бинарный. Разбор: [07-spec-review.md](07-spec-review.md), С5.

## Главное в одном абзаце

ТЗ методологически сильное, и его основное требование — резать ложные находки —
архитектурой поддерживается полностью. Но три количественных требования в паре
несовместимы: порог входа `К_бе(консерв) × 1.05` при `min_sample = 50` не может
быть достигнут ни при каком реальном рынке (нужен перевес над линией 43%, см.
таблицу 1), а разбивка 50 срабатываний по девяти OOS-окнам даёт ~6 событий на
окно с доверительным интервалом шириной 60 п.п. Предлагается поднять минимальную
выборку до 200, перейти на односторонний интервал Уилсона и развести «оценку
процедуры поиска» и «карту жизни конкретной стратегии» — после этого весь
остальной каркас ТЗ реализуем как написан.
