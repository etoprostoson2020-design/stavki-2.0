# 03. Признаки первой очереди и защита от утечки

## Что определяет очередь

Признак попадает в первую очередь, если он считается из данных, которые уже
есть за все десять сезонов **без расхода бюджета API**:

- скелет календаря из `/fixtures?league&season` — 1 запрос на лигу-сезон,
  всего около 100 запросов на весь проект. Даёт точное время начала, стабильные
  `team_id`, стадион, судью, статус и счёт (полный и по таймам);
- CSV football-data.co.uk — удары, удары в створ, угловые, фолы, карточки,
  счёт по таймам за те же сезоны, бесплатно;
- справочники — координаты стадионов, дерби, границы режимов.

Вторая очередь требует поматчевых запросов к API (события, составы, травмы, xG)
и подключается по мере бэкфилла.

Такое разделение позволяет начать этапы 4–6 немедленно, не дожидаясь недельного
бэкфилла (см. Р7).

## Реестр первой очереди

Обозначения: `T` — целевой матч, все окна считаются по матчам с
`known_at < kickoff(T)`. Суффиксы `_3 _5 _10` — размер скользящего окна.
Колонка «мин» — `availability_offset_min`, за сколько минут до матча признак
известен.

### Форма (п. 4 ТЗ)

Все — в трёх окнах `_3 _5 _10`, отдельно суммарно и по месту (дома/в гостях):

`gf_avg`, `ga_avg`, `gd_avg`, `ppg`, `shots_avg`, `shots_against_avg`,

`fouls_avg`, `cards_avg`, `btts_rate`, `over25_rate`, `cs_rate`, `fts_rate`.

Модель «ожидаемых голов по ударам» — простая пуассоновская регрессия на

(см. раздел про утечку). Когда появится xG (вторая очередь), тот же блок
пересчитывается на нём, но как отдельное семейство с собственной картой
доступности по сезонам.

### Тайм-специфика (п. 4 ТЗ)

Доступна уже в первой очереди — счёт по таймам есть и в CSV, и в `/fixtures`.

`h1_gf_avg_5/10`, `h1_ga_avg_5/10`, `h2_gf_avg_5/10`, `h2_ga_avg_5/10`,
`h1_goal_share` (доля голов в первом тайме), `h2_stronger_rate`,
`conceded_first_rate_10`, `scored_first_rate_10`,
`comeback_rate_10` (отыгрался после отставания к перерыву),
`blown_lead_rate_10` (не удержал преимущество перерыва),
`ht_lead_conversion_10`, `ht_draw_rate_10`.

Разбивка голов по 15-минутным интервалам — вторая очередь, нужны события.

### Судья

В CSV football-data судья есть для основных дивизионов; для остальных — из
скелета календаря. Все агрегаты — скользящие и point-in-time.

`ref_cards_pg`, `ref_yellow_pg`, `ref_red_pg`, `ref_fouls_pg`, `ref_pens_pg`,
`ref_home_card_bias` (разница карточек хозяева минус гости),
`ref_n_matches` — обязателен для отсечения малых данных (п. 4 ТЗ).

**Итого первая очередь: около 160 колонок витрины.**

## Сжатие к среднему — обязательно для всех частот

Любой признак вида «доля матчей, в которых…» при малом `n` — чистый шум.
`comeback_rate_10` по десяти матчам принимает всего одиннадцать значений, а
`venue_home_advantage` для только что построенного стадиона не определён вовсе.

Все частотные признаки проходят бета-биномиальное сжатие к соответствующей
базе (лига-сезон для команд, лига для судей и стадионов):

```
p_shrunk = (k + α) / (n + α + β)
```

где `α, β` подбираются методом моментов **на обучающем окне** и хранятся в
`features.registry.shrinkage`. Это не украшательство: без сжатия автомайнинг
будет систематически выбирать команды с малым `n` и экстремальной оценкой, и
такие находки не переживут ни одного OOS-окна.

## Point-in-time: механика

Единственная точка построения — `build_team_match(as_of: datetime | None)`.
Внутри:

1. берётся срез `core`, где `known_at < kickoff(T)` для каждого целевого матча
   (а при заданном `as_of` — дополнительно `known_at < as_of`);
2. агрегаты считаются оконными функциями polars по этому срезу;
3. никакой код признака не имеет прямого доступа к таблицам `core` — только к
   объекту среза, который физически не отдаёт строки из будущего.

Отдельно — **параметры, а не только данные**. Утечка через параметры менее
очевидна и потому опаснее. На обучающем окне и только на нём подбираются:

- границы бинов дискретизации для автомайнинга;
- средние и дисперсии для нормировок;
- коэффициенты `α, β` сжатия к среднему;
- коэффициенты пуассоновской модели ожидаемых голов;
- любые рейтинги силы команд.

## Тесты на утечку (п. 1.4 ТЗ требует их отдельным набором)

### Т1. Тест путешествия во времени — главный

```
1. Построить признаки на полной базе          → F_full
2. Усечь базу по дате T (удалить всё позже)   → base_T
3. Построить признаки на base_T               → F_T
4. Для всех матчей с kickoff < T:  F_full == F_T  побайтово
```

Ловит практически всё: любое обращение к будущему меняет значение при усечении.
Прогоняется на пяти датах T, по одной на сезон. Это самый дешёвый и самый
сильный тест из возможных, и именно он делает Parquet-слой с версионированием
оправданным.

### Т2. Тест порчи будущего

Случайно переписать все результаты после даты T (счета, статистику, события).
Признаки матчей до T обязаны не измениться. Дополняет Т1: ловит случаи, когда
код читает будущие строки, но берёт из них что-то, не меняющееся при усечении.

### Т3. Тест перемешанного будущего

Обучить простую модель предсказывать перемешанный исход по признакам. AUC должен
быть 0.5 в пределах шума. Тест не строгий, но ловит грубые протечки в редко
используемых семействах признаков.

### Т4. Линтер источников

Каждый признак в реестре объявляет `source_tables`. Статическая проверка:
функция признака не обращается к таблицам вне объявленного набора и не содержит
обращений к `core` напрямую. Нарушение — падение сборки, а не предупреждение.

### Т5. Тест горизонта доступности

Для каждой стратегии: все её признаки имеют `availability_offset_min >=`
горизонта решения стратегии. Стратегия на составах с горизонтом «за двое суток»
не собирается — это ошибка конфигурации, а не тихое ухудшение качества.

### Т6. Тест параметров

Пересобрать бины и коэффициенты сжатия на обучающем окне и на всех данных;
значения обязаны различаться. Если они совпали — значит, подбор идёт по всем
данным, и это утечка. Тест «от противного», но работает.

## Что осознанно не считается в первой очереди

| Не считаем | Почему |
|---|---|
| Составы, отсутствие ключевых игроков | доступны за 60 минут до матча; исторические данные ненадёжны (С9) |
| Травмы | `/injuries` отдаёт текущее состояние и обновляется задним числом (С9) |
| xG | доступен примерно с 2021 и не по всем лигам, сокращает окно валидации (С10) |
| Эффект нового тренера | требует истории назначений, которой в API нет в PIT-виде |
| Голы по 15-минутным интервалам | нужны события, вторая очередь после бэкфилла |
| Погода | внешний источник, вторая очередь |

Ни один из них не выбрасывается — все переходят во вторую очередь с явной
пометкой доступности. Правило из п. 14 ТЗ соблюдается: отсутствующие данные не
заменяются пустыми значениями, а сокращают выборку стратегии.
