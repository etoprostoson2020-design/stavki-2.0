# 04. Рынки и расчёт исхода

П. 5 ТЗ: расчёт исхода — детерминированная функция от финального счёта и
статистики матча, вынесенная в отдельный модуль с юнит-тестами.

## Сигнатура

```python
class Outcome(Enum):
    WIN = "WIN"; HALF_WIN = "HALF_WIN"; PUSH = "PUSH"
    HALF_LOSS = "HALF_LOSS"; LOSS = "LOSS"; VOID = "VOID"

def settle(bet: BetSpec, m: MatchResult) -> Outcome: ...
```

Пять исходов вместо двух — это принципиально. ТЗ определяет всю экономику через
`p̂` (п. 1.2), то есть неявно предполагает бинарный исход, но в списке рынков
п. 5 есть азиатские четвертные форы, у которых ставка делится пополам и одна
половина может вернуться. Для них «точность в процентах» неопределена. Это
пробел ТЗ, закрываемый ниже (см. также С5).

`VOID` — отдельно от `PUSH`: матч не доигран, отменён, техническое поражение.
Такие матчи исключаются из знаменателя, а не считаются возвратом.

## Реализуемые рынки

| Семейство | Варианты | Тип исхода |
|---|---|---|
| 1X2 | П1, Х, П2 | бинарный |
| Двойной шанс | 1X, 12, X2 | бинарный |
| Тотал матча | 0.5 / 1.5 / 2.5 / 3.5 / 4.5, ТБ и ТМ | бинарный |
| Тотал матча, азиатский | шаг 0.25 в диапазоне 1.0–4.0 | с возвратом и половинами |
| Индивидуальный тотал | по каждой команде, 0.5–3.5 | бинарный |
| Обе забьют | да / нет | бинарный |
| Тотал 1-го тайма | 0.5 / 1.5 / 2.5 | бинарный |
| Тотал 2-го тайма | 0.5 / 1.5 / 2.5 | бинарный |
| Исход 1-го тайма | 1X2 | бинарный |
| Исход 2-го тайма | 1X2 по голам второго тайма | бинарный |
| HT/FT | все 9 комбинаций | бинарный |
| Точный счёт матча | сетка до 4:4 плюс «прочее» | бинарный |
| Точный счёт 1-го тайма | сетка до 2:2 плюс «прочее» | бинарный |
| Европейская фора | целые, −3…+3 | с возвратом |
| Азиатская фора | шаг 0.25, −2.5…+2.5 | с возвратом и половинами |
| Угловые | тотал (шаг 0.5, 7.5–12.5), фора, кто больше | бинарный и с возвратом |
| Карточки | тотал, кто больше | бинарный и с возвратом |
| Комбинированные | «обе забьют + тотал», «победа + тотал» | бинарный |

Расчёт ведётся по **основному времени** (90 минут плюс компенсированное) — это
общепринятое правило расчёта, и оно должно быть в тестах явно, потому что в
кубковых матчах `core.match` содержит и дополнительное время.

## Обобщённый коэффициент безубыточности

П. 1.2 ТЗ: `К_бе = 1/p̂`. Выведем формулу, которая совпадает с ней на бинарных
рынках и определена на остальных.

Прибыль на единицу ставки при коэффициенте `d`:

| Исход | Прибыль |
|---|---|
| WIN | `d − 1` |
| HALF_WIN | `(d − 1)/2` |
| PUSH | `0` |
| HALF_LOSS | `−0.5` |
| LOSS | `−1` |

Математическое ожидание прибыли:

```
E[прибыль] = (d − 1)·(p_win + p_half_win/2) − (p_loss + p_half_loss/2)
```

Обозначим `A = p_win + p_half_win/2` (эффективная выигрышная масса) и
`B = p_loss + p_half_loss/2`. Приравнивая к нулю:

```
К_бе = 1 + B/A
```

Проверка на бинарном рынке: `p_half_win = p_half_loss = p_push = 0`, значит
`A = p`, `B = 1 − p`, и `К_бе = 1 + (1−p)/p = 1/p`. Совпадает с ТЗ.

Три величины на карточке стратегии, как требует п. 1.2:

| Величина | Формула |
|---|---|
| Точечная | `К_бе = 1 + B̂/Â` по наблюдённым частотам |
| Консервативная | по нижней границе доверительного интервала для `A/(A+B)` |
| Порог входа | консервативная × 1.05 |

Для бинарных рынков нижняя граница — интервал Уилсона (п. 8 ТЗ). Для рынков с
половинами и возвратом интервал Уилсона неприменим, потому что наблюдение не
является испытанием Бернулли; там граница берётся бутстрэпом по вектору
единичных доходностей (см. [05-validator.md](05-validator.md)).

## Алгебраические зависимости между рынками

Рынки не независимы, и движок обязан это знать:

- `тотал матча = тотал 1-го тайма + тотал 2-го тайма`;
- HT/FT полностью определяет исход 1-го тайма и частично — исход матча;
- точный счёт определяет все тоталы, обе забьют, фору и 1X2;
- чётность матча равна XOR чётностей таймов, поэтому конструкция из трёх плеч
  чётности сводится к ставке на одну ячейку (тождество из скилла
  `laliga-loader`, и оно же обобщается на другие семейства);
- «обе забьют» + «тотал 2.5» пересекаются очень сильно.

Практическое следствие: **дедупликация стратегий (п. 7.1 ТЗ) должна работать по
паре «множество сработавших матчей × класс эквивалентности рынка»**, а не по
множеству матчей отдельно. Иначе одно открытие попадёт в выдачу пять раз в
разных обёртках, раздует счётчик гипотез и создаст иллюзию портфеля из пяти
независимых стратегий, который на деле является одной ставкой в пятикратном
размере. Классы эквивалентности задаются таблицей выводимости и проверяются
юнит-тестами на сетке всех счетов до 6:6.

## Юнит-тесты модуля расчёта

П. 5 ТЗ требует отдельный набор. Состав:

1. **Табличные тесты** на каждый рынок: явный список «счёт → ожидаемый исход»,
   включая граничные случаи (ровно 2 гола при тотале 2.5, ничья при форе 0).
2. **Полный перебор сетки счетов** 0:0…6:6 для всех тоталов и фор: проверяется,
   что число исходов каждого типа совпадает с аналитически посчитанным.
3. **Четвертные форы**: для линии −0.75 при победе в один мяч ожидается
   `HALF_WIN`, при ничьей — `HALF_LOSS`; отдельный тест на каждую из восьми
   четвертных линий.
4. **Тождества**: для каждого счёта проверяется согласованность зависимых
   рынков (сумма таймов равна матчу, точный счёт согласован с тоталом и т. д.).
5. **Проверка `К_бе`**: на синтетической выборке с известными вероятностями
   формула `1 + B/A` даёт нулевое матожидание прибыли при `d = К_бе`.
6. **Статусы**: `PST`, `ABD`, `AWD`, `WO` дают `VOID` и не попадают в знаменатель.
